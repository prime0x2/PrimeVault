# PrimeVault — brand assets

Generated by `pnpm build:brand` from the templates in `scripts/brand/`. The
templates port the PrimeVault Brand Pack design (dial-mark logo + Direction B
phosphor / Direction C ember palettes) to standalone HTML so we can render to
PNG headlessly with the Playwright Chromium that's already installed.

## What lives here

| File | Size | Used for |
|---|---|---|
| `icon-ember-{16,32,48,96,128}.png` | n×n | Reference set — Ember (orange) variant |
| `icon-dark-{16,32,48,96,128}.png`  | n×n | Reference set — Dark (charcoal + phosphor) variant |
| `social-dark.png`  | 1280×640 | GitHub social preview — dark variant |
| `social-light.png` | 1280×640 | GitHub social preview — light variant |
| `readme-hero-dark.png`  | 1280×360 | README banner shown on `prefers-color-scheme: dark` |
| `readme-hero-light.png` | 1280×360 | README banner shown on `prefers-color-scheme: light` |

The **live extension icons** (the ones Chrome actually loads) live in
`public/icon/{16,32,48,96,128}.png`. They're the Ember variant. To switch the
toolbar icon to the Dark variant, change `LIVE_ICON_VARIANT` at the top of
`scripts/brand/render.mjs` and re-run `pnpm build:brand`.

## Where each asset is consumed

- **Extension icons** (`public/icon/*.png`) — WXT auto-discovers icons in
  `public/icon/` and wires them into `manifest.icons`. Nothing extra to do
  beyond regenerating the PNGs.

- **README hero** — embedded at the top of the root `README.md` via a
  `<picture>` block that swaps based on GitHub's light/dark theme.

- **GitHub social preview** — there is no in-repo wiring for this. It must be
  uploaded manually once via the GitHub UI:

  1. Go to <https://github.com/prime0x2/PrimeVault/settings>.
  2. Scroll to **Social preview**.
  3. Click **Edit** → upload `docs/brand/social-dark.png` (the dark variant
     reads better on the surfaces GitHub renders previews on — Twitter, Slack,
     Discord, link unfurlers).

  Re-upload only when the brand changes; GitHub doesn't pull from the repo.

## Regenerating

```sh
pnpm build:brand
```

That re-renders every PNG in this directory and the live icons in
`public/icon/`. The script is deterministic — running it on the same templates
should produce byte-identical output, modulo Chromium-version drift on font
hinting.

## Editing the design

The templates are vanilla HTML + inline JS. They mirror the React components
in the original brand pack (`PrimeVault Brand Pack.html` from the design
package), but rewritten so they don't need React at runtime.

- `scripts/brand/icon.html`   — accepts `?variant=ember|dark&size=N`
- `scripts/brand/social.html` — accepts `?variant=dark|light`
- `scripts/brand/hero.html`   — accepts `?variant=dark|light`

To preview a template without re-running the full pipeline, open it directly
in a browser and tack the query string on:

```
file:///path/to/scripts/brand/social.html?variant=dark
```
