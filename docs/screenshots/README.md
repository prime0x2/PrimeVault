# PrimeVault — Chrome Web Store screenshots

Generated by `pnpm capture-shots` from `scripts/screenshots/capture.mjs`. The
script loads the production-built MV3 extension into a real Chromium profile
(same `launchPersistentContext` + `--load-extension` harness as `e2e/fixtures.ts`)
and drives the popup through five scenes, screenshotting each at the
corresponding viewport.

Run prerequisite: `pnpm build` — the script reads `.output/chrome-mv3/`.

## What lives here

| File | Size | Scene |
|---|---|---|
| `raw/01-onboarding.png` | 380×560 | Create vault — strength meter at "very strong · 92%", privacy line under the CTA |
| `raw/02-vault-list.png` | 380×560 | 5 entries, one of each kind, mixed work/personal scope, AWS root expired and GitHub PAT expiring in 7d |
| `raw/03-add-entry.png`  | 380×560 | New-entry form with every field exercised — kind, scope, expiry, tags, note |
| `raw/04-unlock.png`     | 380×560 | Welcome-back unlock, with the "no recovery — re-import backup" copy line |
| `raw/05-options.png`    | 720×900 | Settings page — auto-lock + clipboard timers + theme picker |

The popup CSS is `width: 380px; height: 560px;` (see
`src/entrypoints/popup/style.css`), so 380×560 is the native size. Options is a
full-page tab; 720×900 is `max-w-2xl` (672px) + page padding.

## Uploading to the Chrome Web Store

The CWS dashboard accepts screenshots at **640×400** or **1280×800**. The raw
shots above are the source — for the actual listing they need to be composited
onto a 1280×800 brand frame (popup centered on a backdrop in the same
vocabulary as `docs/brand/social-*.png`). That frame template doesn't exist
yet; treat the raw shots as the foundation.

When the listing goes live the upload point is:

  https://chrome.google.com/webstore/devconsole → Store listing → Screenshots

## Regenerating

```sh
pnpm build
pnpm capture-shots
```

The script is deterministic up to font hinting / date math (the "expires in N
days" entries are computed from `Date.now()` so the visible dates change across
runs). Each scene uses a fresh Chromium profile, so no state leaks between
captures.

## Sample data

The vault-list scene seeds five entries — one of each `ENTRY_KIND` — with
mixed scopes and varied expiry. Insertion order is reverse-chronological in
the UI, so the entries land top-down as: AWS root (expired), GitHub PAT
(expires 7d), Stripe live key, WiFi password, Recovery phrase. Two badges in
the top half, all five kinds, both scopes — that's the storytelling target.

The values themselves are bogus but the *shapes* (`sk_live_…`, `ghp_…`,
`AKIA…`) read as authentic.
